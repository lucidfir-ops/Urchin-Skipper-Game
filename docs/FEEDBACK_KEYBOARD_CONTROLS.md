# September 15 keyboard and remapping feedback

> Historical amendment/implementation record. The current approved design is consolidated in [bible.md](../bible.md). This record preserves provenance; it is not an independent authority or fallback specification.

Authority: the designer's written keyboard/remapping feedback in this session, following the [itch.io TEMP update](FEEDBACK_ITCH_TEMP.md). Bible sections 1, 19 and 20 were checked. This adds keyboard defaults and presentation without changing the definitive controller scheme, boat physics, touch commands or camera.

## Decisions

- Controls / Remapping has Keyboard, Controller and Steam Deck selectors, one diagram at a time, beside the selected device's binding list. Keyboard keycaps show current bindings and highlight the selected action; remapping updates them immediately. Reset acts only on the selected device. Both controller illustrations use the actual active pad profile; selecting a picture does not guess or change hardware mappings.
- [The current controls table](CONTROL_DESIGN.md#keyboard) records the requested keys once. Unrelated shortcuts remain available. Number 1 and number 2 retain the established context-sensitive diver/bag commands. Enter centres rudder at sea and selects in menus. Shift acts on release only when pressed alone, so Shift shortcuts and the shifted + key do not also cycle details. Caps Lock uses its physical held key state, independent of text case.
- Escape opens Pause from water/harbour and closes a menu stack directly to the current location. It never sails home, advances the day or chooses a title/exit action. Planning returns to harbour (or initial boat choice when still pending); completed trips retain the offload receipt. Escape first cancels a pending remap or physical-button naming. Controller Menu, B and visible Back retain their existing history behavior.
- Unmodified keyboard events delivered to the game cancel browser defaults, including unused function keys, page-navigation/search keys and browser Home/Back keys. Dropdown physical capture refocuses the game canvas. Form typing and native dropdown navigation remain usable; Escape and function-key protection also work when a form has focus. Alt/Ctrl/Meta combinations and Shift shortcuts pass through without boat commands. The printed + key remains a game zoom key.
- Game-requested fullscreen asks for browser keyboard handling where supported and falls back on an unsupported-mode response; Chromium's separate keyboard API is scoped to Escape only. Browser/OS-reserved keys, a browser toolbar with focus, and hardware/Steam macros that never deliver a key to the page cannot be suppressed by this HTML game. No global Steam/KDE/Firefox shortcuts were changed. The reported physical keyboard's home-page behavior still needs a physical check; local tests establish delivered-key handling, not its hardware mapping. [Official references](EXTERNAL_REFERENCES.md#keyboard-shortcuts--september-15).

## Saved controls

Untouched previous keyboard defaults migrate to the new keys. Custom keyboard actions keep their keys; conflicting new defaults yield. All saved pad codes, axes, physical names and device profiles remain intact. An additive `urchin-input-before-keyboard-20260915` localStorage copy retains the old shared map, and a keyboard version marker prevents remigrating deliberate later customizations. Keyboard reset is available to apply complete new defaults instead of saved custom keys. Careers and browser profiles are not cleared.

## Verification and exports

Reproduce with `npm run verify -- --unit-only`, then `npm run verify -- --browsers-only --suite=keyboard-feedback`, the `keyboard-feedback-firefox` variant and `--suite=controller`. The keyboard suite checks diagrams at 1280×800 and 1024×640, every bound key's presence, remapping/reload, separate neutral commands, helm routing, diver selection/deployment, Escape from water/harbour/dropdowns, and browser focus/navigation protection. Existing controller and nested/iframe hosting flows provide regression coverage. Both tested engines retain fullscreen after Escape and open the game menu (Chromium 153 / Firefox 155). Physical USB Xbox, Deck and the reported keyboard remain designer playtests.
